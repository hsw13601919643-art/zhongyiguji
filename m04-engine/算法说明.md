# 推荐算法说明

> 对应验收项：M04-01 至 M04-08 ｜ 代码：`m04-engine/engine.js`、`m04-engine/rules.js` ｜ 测试：`m04-engine/index.html`
> 状态：初稿，规则内容待甲方专家确认

## 1. 总体思路

采用方案 4.2(3) 规定的“规则引擎 ＋ 标签匹配”方式：
- **标签匹配**：每首药膳方带有体质、脏腑、季节/节气、年龄、餐次、四气五味、五色、功效标签；用户输入与标签比对打分。
- **规则引擎**：管理员可配置的“条件 → 偏好/规避”规则，体现中医体质学说、脏腑学说、五行学说及“三应”原则（应时、应地、应体）。

不使用机器学习，结果完全可解释：每条推荐都列出匹配原因与触发的规则。

## 2. 输入

| 输入 | 来源 | 说明 |
|---|---|---|
| 体质 | 体质问卷判定结果，或用户手动选择 | 可不选 |
| 节气 | 默认当天节气（系统计算），可手动切换 | 决定季节；小暑、大暑视为“长夏” |
| 调理脏腑 | 肝、心、脾、肺、肾，可不选 | |
| 年龄段 | 儿童、青少年、青年、中年、老年 | 可不选 |
| 地域 | 江南、华北、西北、东北、岭南、西南、其他 | 默认江南（应地） |

## 3. 计算步骤

1. **取候选**：只取“已发布”的方剂（未经专家审核的方剂不进入推荐）。
2. **合规过滤**：组成中“药材”类须全部在 106 种药食同源目录内，否则过滤（管理端可改为“仅标注”模式）。
3. **标签打分**（分层，上一层分值大于下面各层之和，保证“辨体施膳”优先）：

| 层级 | 条件 | 分值 |
|---|---|---|
| 体质 | 方剂“适用体质”含用户体质 | 200 |
| 脏腑 | 方剂“调补脏腑”含所选脏腑 | 80 |
| 时令 | 精确匹配节气 50；匹配季节 40；时令方（非四季通用）再加 5 | 40—55 |
| 年龄 | 方剂“适用年龄”含用户年龄段 | 10 |
| 五行 | 方剂五色、五味与所选脏腑及当令季节对应（肝-青-酸、心-赤-苦、脾-黄-甘、肺-白-辛、肾-黑-咸） | 各 5 |

4. **规则加减分**：对每条已启用且条件满足的规则，方剂命中“偏好”任一项加该规则权重，命中“规避”任一项扣该规则权重；加分合计上限 30。
5. **三餐分配**：按方剂“适用餐次”分别为早、午、晚选出得分最高者，另给 2 个备选。同一方剂尽量不在一天内重复——只在同一匹配层级内比较，不会为了换花样而牺牲体质、脏腑或时令匹配。
6. **四季方案**：分别以春分、夏至、秋分、冬至为代表节气，各生成一套三餐方案。

## 4. 默认规则

| 分组 | 规则 | 依据 |
|---|---|---|
| 方案示例 | R01 春季＋肝＋气郁质 → 疏肝理气、酸味青色；R02 冬季＋肾＋阳虚质 → 温补肾阳、黑色；R03 老年＋脾＋气虚质 → 健脾益气、粥羹易消化 | 方案 4.2(3) |
| 应体 | R10—R18 九种体质宜忌（如阳虚忌寒凉、湿热忌温热、特禀避鱼腥发物） | 中医体质学说 |
| 应时 | R20—R24 四季及长夏 | 《素问·四气调神大论》、五行学说 |
| 应地 | R30—R34 江南、北方、岭南、东北、西南 | “三应”原则 |

## 5. 性能

纯前端版在普通电脑上单次推荐耗时约 1 毫秒（33 首方剂、23 条规则）。数据规模增至数千首时，可在二期服务器端预建标签索引，仍能满足“响应时间 < 3 秒”（验收项 M05-06）。

## 6. 测试

`m04-engine/index.html` → “覆盖测试”：一键运行 43 个用例（A 组九种体质、B 组二十四节气、C 组五脏、R 组典型规则与合规过滤），结果可导出 CSV 填入验收表《推荐覆盖测试》。

## 7. 局限与后续

- 体质、脏腑、季节等标签为人工标注，推荐质量取决于标注质量，须专家审核。
- 示例数据仅 33 首，部分组合（如血瘀质晚餐）可选方剂少，会出现同一方剂早晚重复；正式数据导入后自然改善。
- 推荐结果仅作日常饮食参考，不能替代诊疗；页面均有提示。
