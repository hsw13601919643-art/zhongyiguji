# 经典药膳方数据库设计说明书

> 项目编号：PDZY-2026-0315 ｜ 版本：V1.0（纯前端演示版） ｜ 对应验收项：M01-05、M01-06，交付物清单第 1 项
> 状态：初稿，待甲方确认

## 1. 设计目标

1. 结构化收录中医经典古籍中的药膳方，满足方案 4.1(2) 规定的 13 个必备字段。
2. 为“三餐四季”推荐系统（M04）提供可计算的标签：体质、脏腑、节气、餐次、四气五味、五色、功效标签。
3. 内置国家卫健委《药食同源目录》（106 种），对每首方剂自动核验药食同源合规性。
4. 支持批量导入、在线编辑、版本管理与专家审核（M01-07 至 M01-12）。

## 2. 存储方案

| 阶段 | 存储位置 | 说明 |
|---|---|---|
| 一期（当前） | 浏览器本地存储（localStorage，键前缀 `ys_`） | 无需服务器，便于需求确认与演示；数据只保存在当前浏览器 |
| 二期 | MySQL 或 PostgreSQL（部署在甲方指定服务器或云平台） | 表结构见第 6 节；页面通过 `assets/js/db.js` 统一读写，替换实现即可 |

示例数据文件：`m01-database/data/recipes.js`（药膳方）、`yaoshi-106.js`（药食同源目录）、`dicts.js`（标准字典）。

## 3. 药膳方字段定义

### 3.1 必备字段（方案 4.1(2)）

| # | 字段 | 键名 | 类型 | 必填 | 取值规范 |
|---|---|---|---|---|---|
| 1 | 方名 | `name` | 文本 | 是 | 与古籍原文一致；异名记入 `alias` |
| 2 | 出处 | `source.book` / `source.chapter` / `source.original` / `source.edition` | 对象 | 古籍名称必填 | 古籍名称不带书名号；卷次篇目如“卷二·食疗诸病”；原文摘录；版本 |
| 3 | 组成 | `composition[]` | 数组 | 是 | 每项：名称 `name`、标准名 `std`（与目录名称不一致时填写，如“生地黄汁→地黄”）、用量 `amount`、类型 `type`（药/食/调料） |
| 4 | 功效 | `efficacy` | 文本 | 是 | 中医功效术语，如“温中补血，祛寒止痛” |
| 5 | 适用年龄 | `ages[]` | 多选 | 否 | 儿童（3—12 岁）、青少年（13—17 岁）、青年（18—44 岁）、中年（45—59 岁）、老年（60 岁及以上） |
| 6 | 适用体质 | `constitutions[]` | 多选 | 否 | 平和质、气虚质、阳虚质、阴虚质、痰湿质、湿热质、血瘀质、气郁质、特禀质 |
| 7 | 调补脏腑 | `organs[]` + `indication` | 多选 + 文本 | 否 | 肝、心、脾、肺、肾；病症记入“主治病症” |
| 8 | 适用节气 | `seasons[]` + `terms[]` | 多选 | 否 | 季节：春、夏、秋、冬（四季皆宜则全选）；节气：二十四节气标准名，可为空（表示该季全部节气） |
| 9 | 药食同源应用 | 系统计算 | — | — | 组成中“药”类全部在 106 种目录内即为合规；不合规方剂不进入推荐 |
| 10 | 制作方法 | `method` | 文本 | 否 | 烹饪、炮制、加工工艺，参照《药膳制作通用规范》；现代参考用量须注明 |
| 11 | 注意事项 | `cautions` | 文本 | 否 | 禁忌、慎用人群 |
| 12 | 现代研究 | `research[]` + `researchNote` | 数组 + 文本 | 否 | 每条：题名、作者、刊名、年份、链接；摘要写入 `researchNote` |
| 13 | 数据来源 | `dataSource` | 文本 | 否 | 古籍原文版本、页码、数据库链接 |

### 3.2 扩展字段（推荐算法所需）

| 字段 | 键名 | 取值 | 用途 |
|---|---|---|---|
| 适用餐次 | `meals[]` | 早、午、晚 | 三餐方案分配（必填） |
| 膳食类别 | `category` | 粥、汤、羹、茶饮、菜肴、糕点 | 规则偏好（如老年宜粥、羹） |
| 四气 | `nature` | 寒、凉、平、温、热 | 体质宜忌（如阳虚忌寒凉） |
| 五味 | `tastes[]` | 酸、苦、甘、辛、咸 | 五行对应（肝-酸 等） |
| 五色 | `colors[]` | 青、赤、黄、白、黑 | 五行对应（肾-黑 等） |
| 功效标签 | `tags[]` | 见 `dicts.js` 中 `tags` | 规则引擎标签匹配 |

### 3.3 流程字段

| 字段 | 键名 | 说明 |
|---|---|---|
| 编号 | `id` | `YS` + 4 位序号，如 YS0001 |
| 状态 | `status` | draft 草稿 → pending 待审核 → approved 审核通过 → published 已发布；rejected 已驳回；offline 已下架 |
| 审核人 / 审核时间 | `reviewer` / `reviewedAt` | 专家审核留痕（M01-12） |
| 标准化打样 | `standardized` / `sampleRecord` | 40 方打样完成情况（M01-14） |
| 版本 | `version` | 每次保存递增；历史版本另存（M01-10） |
| 示例标记 | `sample` / `verify` | 示例数据标记，正式数据导入后为 false |

## 4. 药食同源目录

- 构成：2002 年名单 87 种 + 2019 年新增 6 种 + 2023 年新增 9 种 + 2024 年新增 4 种，共 106 种。
- 每项字段：序号、名称、别名、批次、备注（使用限制）。
- 匹配规则：组成项的“标准名”优先，其次“名称”；支持别名（如 陈皮→橘皮、薯蓣→山药、苏子→紫苏籽）。
- **待办**：由甲方对照国家卫健委、市场监管总局公告原文逐一核对（验收项 M01-02）。

## 5. 标准字典

见 `m01-database/data/dicts.js`，包括九种体质（特征与饮食调养）、五脏五行对应、二十四节气及养生提示、年龄段、餐次、膳食类别、四气五味五色、功效标签、地域（应地）、古籍书目、状态。字典修改须同步本说明书。

## 6. 二期数据库表结构（建议）

| 表 | 主要字段 |
|---|---|
| `recipe` | id, name, alias, book, chapter, original, edition, efficacy, indication, method, cautions, research_note, data_source, category, nature, status, standardized, sample_record, reviewer, reviewed_at, version, created_by, created_at, updated_at |
| `recipe_ingredient` | recipe_id, seq, name, std_name, amount, type |
| `recipe_tag` | recipe_id, dim（age/constitution/organ/season/term/meal/taste/color/tag）, value |
| `recipe_research` | recipe_id, title, authors, journal, year, url |
| `recipe_version` | recipe_id, version, snapshot(JSON), user, note, created_at |
| `yaoshi_item` | no, name, aliases, batch, note |
| `rule` | id, name, enabled, when_json, prefer_json, avoid_json, weight |
| `content` | id, title, category, type, summary, body, video_url, status, updated_at |
| `app_user` | id（匿名设备号）, constitution, age_group, region, src, first_seen, last_seen |
| `rec_log` | id, user_id, input_json, picks_json, ms, src, created_at |
| `visit_log` | id, user_id, page, src, created_at |
| `admin_user` / `audit_log` | 管理账号、角色；操作日志 |

不设患者姓名、身份证号、病历等字段（方案 4.1(4)、八.3）。

## 7. 数据导入导出

- 模板：`m01-database/template/recipe-import-template.csv`（UTF-8，Excel 可直接打开）。
- 多值字段用“、”分隔；组成写作“名称:用量:类型”，多项用“；”分隔，标准名不同时写作“生地黄汁=地黄:一升:药”。
- 导入时逐行校验，错误行给出行号与原因，正确行以“待审核”状态入库。
- 管理端可将全部数据导出为同格式 CSV，作为“结构化数据库”交付文件。
